# Блок 6.5 — Мультиагентные системы: сравнительный отчёт

## 1. Постановка задачи и тестовый набор

### Сценарий

**Вход:** пользователь задаёт вопрос на русском языке по юридическим документам
(договорам, кадровым политикам, корпоративным актам, судебным решениям).

**Роли агентов:**
- `researcher` — получает вопрос, ищет релевантные факты в корпусе через
  инструмент `search_knowledge_base` и возвращает маркированный список фактов
  с указанием источников; финальный ответ пользователю не пишет.
- `writer` — получает список фактов от researcher и составляет связный ответ
  на русском с цитированием источников в формате [1], [2]; если фактов
  недостаточно, сообщает об этом супервизору.
- `supervisor` (только в мультиагентной реализации) — координирует работу:
  сначала направляет запрос к researcher, затем к writer; может запросить
  повторный поиск при неполных фактах.

**Ожидаемый формат финального ответа:** связный текст на русском языке с
конкретными цитатами из документов, ссылками на источники в формате [N] и
явным указанием, если ответ выходит за пределы корпуса.

> Сценарий одинаков для мультиагентной и single-agent реализаций —
> инструмент `search_knowledge_base` идентичен в обоих скриптах.

---

### Тестовый набор (5 вопросов)

| # | Тип | Вопрос |
|---|-----|--------|
| Q1 | по корпусу | Каков размер неустойки за просрочку оплаты по договору поставки товара? |
| Q2 | по корпусу | Какие основания для досрочного расторжения трудового договора предусмотрены в кадровых документах? |
| Q3 | по корпусу | Какие условия конфиденциальности установлены в соглашении между юридическими лицами? |
| Q4 | многошаговый | Если сотрудник нарушил политику информационной безопасности и это привело к разглашению коммерческой тайны — какие меры ответственности предусмотрены в документах компании? |
| Q5 | вне базы | Каков порядок регистрации товарного знака в Роспатенте? |

**Q1–Q3** проверяют точный поиск фактов из конкретных документов.  
**Q4** требует сопоставления двух документов (политика ИБ + положение о коммерческой тайне).  
**Q5** выходит за пределы корпуса — ожидаем явный отказ без галлюцинаций.

## 5. Сопоставление с Anthropic-ориентиром

По данным Anthropic («How we built our multi-agent research system», июнь 2025),
их мультиагентная система дала +90.2% к качеству при ~15× росте токенов.
Это достигнуто на **breadth-first research** — широком поиске по десяткам
независимых источников, где параллельные агенты не дублируют работу друг друга.

В нашем эксперименте:
- Множитель токенов: **3.1×** (против 15× у Anthropic) — задача слишком
  простая для мультиагентности, разрыв не раскрылся.
- Прирост качества: **отсутствует** (на Q5 — регресс).
- Причина: задача является **tight-coupling** (один RAG-корпус, один вопрос,
  один финальный ответ) — именно тот случай, где Anthropic предупреждает
  о проигрыше мультиагента.

---

## Решение

**НЕ использовать мультиагентную систему в дипломном проекте.**

Обоснование: задача юридического ассистента — поиск в едином корпусе и
формирование одного ответа — обладает тремя признаками, при которых
Anthropic рекомендует single-agent:
1. **Tight coupling** — researcher и writer разделяют один контекст (RAG-корпус),
   изоляции ролей не требуется.
2. **Write-heavy** — финальный текст генерируется единожды, второй агент
   добавляет только дополнительный LLM-вызов.
3. **Real-time** — latency 8.6 с против 3.2 с критично для чат-интерфейса.

Собственные числа подтверждают выбор: 3× токенов, 2.7× latency, регресс
по надёжности на вопросах вне базы.

**Итог agent-слоя диплома:** один `create_agent` (или персистентный ReAct-граф
из Б6.4) с инструментами `search_knowledge_base`, `get_current_time`,
`send_email`. Мультиагент остаётся как изученный паттерн с обоснованным
отказом на защите.
